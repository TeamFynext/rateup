## Creating a Field

<Steps>
<Step>
Click **Add Custom Field**.
</Step>
<Step>
Give it a clear **name** — this is what your team sees on every contact record.
</Step>
<Step>
Choose the field type.
</Step>
<Step>
Save. The field appears on every contact.
</Step>
</Steps>

Use **Edit Custom Field** to change one later.

## Where Custom Fields Appear

| Location | Use |
|----------|-----|
| **Contact record** | Viewing and editing the value |
| **Ticket Details panel** | Agents see it while replying |
| **Contact filters** | Segmenting on the value |
| **Import** | Populating in bulk |

## Custom Fields vs Labels

The choice is about what kind of thing you are storing:

| | Custom fields | [Labels](/contacts/labels) |
|---|--------------|--------|
| **Store** | A value — a number, a date, text | A yes/no trait |
| **Example** | *Membership number: 4471* | *VIP* |
| **Visible in the Inbox list** | No | Yes |

If the answer is "yes or no", use a label. If the answer is "which one" or "how much", use a
custom field.

---

## Designing Fields Well

<Callout type="warn">
  Every field you add is a field someone has to fill in. Fields that are half-populated are worse
  than no field, because nobody trusts them.
</Callout>

- Add a field only when you know what you will do with the data
- Name it so its meaning is obvious to someone who joined last week
- Populate existing contacts by [import](/contacts/managing-contacts) rather than by hand
- Review yearly and remove fields nobody fills in
