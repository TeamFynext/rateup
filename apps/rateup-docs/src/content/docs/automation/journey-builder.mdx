Opening a journey from the [Journeys](/automation/journeys) list opens the **builder** at
`/dashboard/automation/journeys/<id>`: a canvas of connected nodes, one node per thing the journey
says or does. It is the same builder on every channel; what it offers follows the journey's own
channel.

<ScreenShot src="/docs/screenshots/whatsapp/chatbot-builder.png" alt="The journey builder" />

---

## The Four Regions

| # | Region | What it is |
|---|--------|-----------|
| 1 | **Canvas** | The journey itself — nodes and the arrows between them |
| 2 | **Toolbar** (top centre) | Save, validate, undo/redo, auto layout, settings |
| — | **Start card** (bottom centre) | Shown while nothing starts the journey yet — see [Switch It On](#switch-it-on) |
| 3 | **Components panel** (right) | The nodes you can add. Becomes the **node editor** when you select a node |
| 4 | **Controls** (bottom left) and **minimap** (bottom right) | Zoom in and out, fit to view, lock the canvas — and a map of a journey too big for one screen |

---

## Add and Connect a Node

<Steps>
<Step>
**Drag** a component from the right-hand panel onto the canvas. It lands where you drop it.
</Step>
<Step>
**Drag from one node's handle to another's** to connect them. The arrow is the path the conversation
takes.
</Step>
<Step>
**Click a node** to open its editor in place of the Components panel. Fill in the message, media,
buttons or settings it needs.
</Step>
</Steps>

The builder saves on its own about a second after you stop changing the canvas. **Save** in the
toolbar writes straight away; it greys out to *"All changes saved"* once nothing is waiting.

<Callout type="warn">
  Saving is not the same as going live — and the reverse is true too. A journey that customers are
  already reaching picks up every saved change at once, half-finished edits included. Clone a live
  journey and edit the copy instead.
</Callout>

## The Toolbar

| Control | Does |
|---------|------|
| **Save** | Writes the journey now rather than waiting for the automatic save. Disabled — *"All changes saved"* — when there is nothing to write |
| **Validate flow** | Checks the structure and reports the first problem it finds |
| **Undo** / **Redo** | `Ctrl`/`Cmd` + `Z` and `Ctrl` + `Y` also work |
| **Auto layout** | Re-arranges every node — **Vertical** or **Horizontal** — then fits the view |
| **Settings** | Opens **Journey settings** (below) |
| **Preview** (top right) | Runs the journey in a phone frame |

## Components

The panel groups nodes by what they do. Components that the journey's channel does not support are
hidden, so an Instagram journey and a WhatsApp one show different lists.

| Group | Nodes | Channels |
|-------|-------|----------|
| **Basic Messages** | Text · Image · Video · Audio | All three |
| | Document | WhatsApp, Messenger |
| **Interactive** | Input | All three |
| | Reply Buttons · List · Call-To-Action URL · Template · Catalog | WhatsApp |
| **Templates** | Cards · Quick Reply | Instagram, Messenger |
| | Product Template · Follow Check | Instagram |
| **Location & Contacts** | Location · Contacts | WhatsApp |
| **Flow Control** | Pause · Start | All three |
| | WhatsApp Flow | WhatsApp |
| **None Interactive** | Assign | All three |
| | Lead | WhatsApp |

The Instagram and Messenger nodes are covered on [Instagram Journeys](/instagram/journeys#what-an-instagram-journey-can-send)
and [Messenger Journeys](/messenger/journeys#what-a-messenger-journey-can-send).

### Nodes worth knowing

| Node | What it needs, and what to watch |
|------|----------------------------------|
| **Start** | Where the journey begins. Its **Start Message** field is read-only. Exactly one per journey — what starts it is the rule, not this node |
| **Text** | Up to **1024** characters |
| **Reply Buttons** | A body, an optional header and footer (footer max **60** characters), and up to **3** buttons |
| **List** | A **Button Text**, then sections with rows — each row has a title and an optional description |
| **Call-To-Action URL** | **Button Text** and the URL that opens when it is tapped |
| **Input** | Collects one answer — text, number, email, phone or date |
| **WhatsApp Flow** | Opens a [flow](/whatsapp/flows) for structured input |
| **Template** | Sends an approved [template](/whatsapp/templates) |
| **Pause** | **Pause Duration** plus a unit — **Seconds** or **Minutes** |
| **Assign** | **Assign To Me** or **Assign To Staff**; for staff, optionally **Assign only if assignee is online** |
| **Lead** | WhatsApp only. Lets a Meta lead ad form start the journey — the wizard's **Lead ad form** choice relies on it. One per journey, for lead journeys only |

## Validating Before You Save

**Validate flow** answers a question the canvas cannot: is this journey actually runnable? It reports the
first thing that is wrong.

| Message | Meaning |
|---------|---------|
| *"Flow is empty. Please add some nodes."* | Nothing on the canvas |
| *"Flow must have a start node."* | Add a **Start** node |
| *"Flow must have exactly one start node."* | Delete the spare one |
| *"Only one start node is allowed in the flow."* | Shown while you drag a second one in |
| *"First node should be a Lead Node."* | A lead automation has to open with **Lead** |
| *"Only one Lead node is allowed"* | Delete the spare one |
| *"Lead node is only allowed lead automation"* | Remove the **Lead** node from an ordinary journey |

A clean structure reports *"Flow validation successful!"*.

<Callout type="info">
  Validation checks the shape of the journey, not its wording or its dead ends. A journey can validate
  perfectly and still trap a customer in a loop — that is what the preview is for.
</Callout>

---

## Preview

**Preview** runs the journey in a phone frame, following the same arrows a customer would.

Walk it end to end and check every button leads somewhere, no path dead-ends, and the customer can
always reach a person.

## Switch It On

A card at the bottom of the canvas says when nothing can start the journey yet:

| Card | What to do |
|------|------------|
| **This journey is off** | The rule the wizard made is still switched off. Type the keyword if it asks for one, then **Switch on** — or **Edit rule** to open the rule |
| **Set up the trigger** | No rule exists. **Create the rule** opens the rule builder with the channel and trigger filled in |
| **This journey is switched off** | The journey is off on the Journeys list. **Switch on** |

On Messenger, a **Get Started button** journey whose Page has no Get Started button yet says
*"Switching it on also adds a Get Started button to your Page."* See
[Journeys → Switch It On](/automation/journeys#switch-it-on) for when each card appears.

## Journey Settings

The **Settings** button opens **Journey settings** — **Basic Information**:

| Field | Notes |
|-------|-------|
| **Journey Name** | Required, at least 3 characters. An internal name — customers never see it |
| **WhatsApp Account** | WhatsApp journeys only. Optional — *"Link a specific phone number only when your flow sends outgoing WhatsApp messages."* |

Click **Save changes** — *"Journey settings saved"*. Closing with unsaved edits asks **Discard
Changes?** — **Keep Editing** or **Discard**.

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| **Save** is greyed out | There is nothing to save | Everything is already written |
| *"Failed to load the journey"* | It could not be loaded, or it was deleted | Click **Retry** |
| A node cannot be dropped | The channel does not support it | Check the group is offered for this journey's platform |
| Customers never reach a node | Nothing connects to it | Drag an arrow into it, then validate |
| The canvas is unreadable | Nodes have drifted | **Auto layout → Vertical** |
