**Knowledge** is what the agent knows about you. Four panels, each a different kind of source.

---

## Business Info

Structured facts about the business, kept as fields rather than prose so the agent quotes them
consistently.

| Field | What goes in it |
|-------|-----------------|
| **Business description** | What you sell and to whom |
| **Contact email** | Where customers reach a human |
| **Hours of operation** | When you are open |
| **Purchase info** | How customers order, minimums, bulk pricing |
| **Payment methods** | For example: cards, UPI, net banking, cash on delivery |
| **Delivery and shipping** | Dispatch times, courier partners, shipping charges |
| **Return policy** | For example: unopened items can be returned within 14 days |

---

## FAQs

Question-and-answer pairs the agent can quote verbatim. Use **Create FAQ** to add one, then **Edit
FAQ** to revise it.

Anything a customer asks weekly and that has one correct answer belongs here rather than in a
skill — an FAQ is the answer itself, a skill is the instruction for finding one.

---

## Files

Documents the agent reads for background: price lists, policy PDFs, product sheets. A file of an
unsupported type is refused on upload.

---

## Websites

Pages the agent crawls for content. Each entry shows its status — **Crawling**, **Crawled** or
**Failed** — so you can tell a page that has not been read yet from one that could not be.

<Callout type="warn">
  Everything here is customer-facing by proxy. An out-of-date return policy or price list is worse
  in the agent's mouth than on a web page, because the customer will read it as a promise.
</Callout>
