**Test** is the working page: four cards that exercise the agent — most of them without involving a
customer. It is never ticked on the setup guide; it is the page you come back to after every change.
Once the agent is live, the setup guide's **Open test console** button brings you here.

## Chat With the Agent

**Test the agent** sends a message to the agent and shows the reply. No real customer is notified,
so it is the safe way to check a new skill or connector tool.

<Steps>
  <Step>Type a **Test message**, such as *"Where is my order #12345?"*</Step>
  <Step>Click **Send**. The reply appears below, with any quick replies as chips.</Step>
  <Step>Keep typing to continue the same conversation — each message follows on from the last, so multi-turn behaviour can be tested.</Step>
  <Step>Click **Start a new conversation** to begin again from scratch.</Step>
</Steps>

A **Handoff: …** badge means the agent would have handed this conversation to your team, and why. **No
response: …** means it chose not to answer, and why.

## Send a Business Event

A business event tells the agent something happened on your side — an order shipped, a booking
moved — so it can reach out first.

| Field | What goes in it |
|-------|-----------------|
| **Consumer phone number** | The customer to tell, with the country code |
| **Event type** | A stable key you choose, reused for every event of this kind, such as `order_shipped` |
| **Description** | What this event means, in words the agent can act on — for example *"The customer's order has left the warehouse."* |
| **Payload** | JSON the agent may quote from — order numbers, dates, links. Up to 4,096 characters |

Click **Submit event**. The card then shows the event's status as Meta reports it, with the error
message or the reason it was skipped if it did not go out.

<Callout type="warn">
  Unlike a test message, a business event reaches a real customer: the agent may message the number
  you enter. Use your own number while you are trying it out.
</Callout>

## Hand a Conversation Back to Meta AI

When a conversation is handed over, Meta AI stays silent for that customer until it is handed back.
**Thread control** does that from here.

<Steps>
  <Step>Enter the customer's **Consumer phone number**, with the country code.</Step>
  <Step>Click **Release to Meta AI** to give up control, or **Pass to Meta AI** to name Meta AI as the new owner.</Step>
</Steps>

Both hand the conversation back and Meta AI answers the customer again. Either only works while your
team holds the conversation. The same thing can be done from the conversation itself in the
[inbox](/inbox/responding-to-conversation), and by closing the ticket if **Hand back to Meta AI when
a ticket is closed** is on in [Go live](/meta-agent/go-live#decide-what-happens-after-a-handover).

## Run an Evaluation

Meta simulates conversations against your scenarios and scores how the agent handled them.

<Steps>
  <Step>Click **Load eval cases** to fetch the scenarios configured for this number. Each shows its categories, its **Suite** version and how many turns it runs to.</Step>
  <Step>Tick the cases to run, or **Select all**.</Step>
  <Step>Click **Run … evaluations**.</Step>
</Steps>

The run reports **QUEUED**, then **RUNNING** with a progress bar, then a **Conversation score**, a
**Turn score** and a summary — or **FAILED**, with the error and the ids of the cases that failed.
**Reload cases** refreshes the list.

<Callout type="info">
  Evaluations are how you tell whether a change to knowledge or skills actually improved anything.
  Run one before and after a substantial edit rather than judging by a single test message.
</Callout>
