# apps/mobile (@rateup/mobile)

The RateUp mobile app for businesses (iOS and Android): the team inbox and chat, voice calls,
loyalty (the cashier counter), forms, flows and web-form responses, teams, and shop orders. It
is an Expo app (React Native, Expo Router file routes) that talks to rateup-api.

## Commands

This app is its own pnpm install, not part of the root workspace: `pnpm-workspace.yaml` here
sets `nodeLinker: hoisted` (the flat node_modules Expo was built on) and `pnpm-lock.yaml` here
is its lockfile. Shared monorepo code comes in as `link:` dependencies (`@rateup/utils`), which
`metro.config.js` adds to Metro's watch folders. Run every command below in this folder.

```bash
pnpm install                  # or `pnpm run install:mobile` at the monorepo root
pnpm start                    # Expo dev server (expo start)
pnpm run android              # native build + run (expo run:android); `source use-java17.sh` first
pnpm run ios                  # native build + run (expo run:ios)
pnpm run typecheck            # tsc --noEmit (typecheck:watch to watch)
pnpm run lint                 # oxlint src (lint:ox:fix to fix)
pnpm run format               # vp fmt . (format:check to check only)
pnpm test                     # Vitest, run once (test:watch to watch)
pnpm run brand:assets         # regenerate icons and splash from assets/brand/ (outputs are committed)
pnpm run ota:android "msg"    # production OTA update (ota:ios for iOS), see below
```

Git hooks live at the monorepo root (`.vite-hooks/`, rules in the root `vite.config.ts`):
pre-commit runs this app's `oxlint --fix` (its `.oxlintrc.json`, skipping `.agents/`) and
`vp fmt` on staged files; pre-push runs every package's `typecheck`, this app's included.

## Project Overview

- **Framework:** Expo (React Native), Expo Router with typed routes, TypeScript
- **Data:** TanStack Query (`src/config/queryClient.ts`) over axios (`src/config/axios.ts`),
  Zustand stores in `src/store/`
- **Auth:** SuperTokens (`supertokens-react-native`), with Google and Apple sign-in; the axios
  instance carries the SuperTokens interceptors
- **Styling:** NativeWind (`tailwind.config.js`, `src/global.css`) plus the design-system palette
  in `src/constants/colors.ts` and `inboxDesign.ts`; fonts are Figtree and Instrument Sans
- **Calls:** `react-native-webrtc`, CallKit on iOS (`plugins/withIosCallKit.js`), and the local
  Android module `modules/rateup-calls`
- **Builds:** EAS (`eas.json`: `development`, `preview`, `production` profiles and channels);
  OTA updates through `expo-updates`, runtime version = app version

## Directory Structure

```
src/
├── app/            # Expo Router routes: auth/, protected/ ((tabs)/, chat/, flow/, ...), _layout.tsx
├── api/            # rateup-api calls, one folder per domain (inbox, loyalty, survey, teams, ...)
├── components/     # screens' building blocks, by feature; shared pieces in common/
├── config/         # env, axios, queryClient, SuperTokens, Google config
├── constants/      # colours, design values, enums, countries
├── context/        # AuthContext, LifecycleContext
├── hooks/          # useOrgModules, usePermissions
├── store/          # Zustand stores (inbox, calls, cashier, ...)
└── utils/          # helpers; tests sit next to the code as *.test.ts
modules/rateup-calls/   # local Expo module (Android only)
plugins/                # Expo config plugins referenced from app.json
scripts/                # brand assets, OTA updates
.agents/skills/         # vendored Expo skills (skills-lock.json), not project code
```

`android/` and `ios/` are generated by prebuild and gitignored. Native changes go through
`app.json` and the config plugins in `plugins/`, never by editing the generated folders.

## Key Conventions

- **Imports:** `@/…` maps to `src/` and `@/assets/…` to `assets/` (tsconfig `paths`, mirrored
  in `vitest.config.mts`).
- **Logging:** use `src/utils/logger.ts`, never `console`. Release builds log nothing, because
  Android logcat is readable by other tooling and the app handles tokens and customer messages.
  oxlint's `no-console` enforces it.
- **Environment:** every `EXPO_PUBLIC_*` value must be read as a direct
  `process.env.EXPO_PUBLIC_…` expression, since that is what Expo inlines. A release build
  refuses to start unless `EXPO_PUBLIC_API_URL` is set and `https://` (`src/config/env.ts`).
- **OTA updates:** publish only with `pnpm run ota:android` / `ota:ios`. The script loads
  `.env.prod` before `eas update`; running `eas update` by hand bundles the local `.env` and
  once shipped a dev tunnel URL to every user.
- **Native module:** `modules/rateup-calls` exists only on Android. Its JS wrapper is a no-op on
  iOS and on builds without the module, so callers never branch on platform.
- **Vendored skills:** `.agents/` belongs to upstream. Do not lint, format or edit it; load the
  relevant skill (for example `building-native-ui`, `upgrading-expo`) before related work.
- **Formatting/linting:** oxfmt + oxlint, never Prettier or ESLint.
